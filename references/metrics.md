# 体检指标定义与局限

`scripts/prose_scan.py` 的测量口径。用之前先读这一页，避免把启发式当判据。

```bash
python3 scripts/prose_scan.py --file draft.tex --paper      # 论文
python3 scripts/prose_scan.py --file notes.md               # 通用
python3 scripts/prose_scan.py --file draft.tex --paper --json
python3 tests/run_cases.py                                  # 回归（改阈值后必跑）
```

---

## 零、LaTeX 预处理（v2.1，实测后加的）

在两篇真实投稿的 .tex（正文与附录共 4 份）上跑出来的教训：**直接在源码上统计会得到完全错误的数字**。现在的处理顺序固定为

```
strip_preamble → strip_comments → strip_floats → clean_tex → drop_heading_lines
```

| 步骤 | 去掉什么 | 不去掉会怎样（实测） |
|---|---|---|
| `strip_preamble` | `\begin{document}` 之前、`\end{document}` 之后 | `microtype.`、`Supplemental Material` 被当成 1 词句 |
| `strip_comments` | `%` 到行尾 | `%-----------` 分隔线被算成 170 个破折号（24/千词） |
| `strip_floats` | table / tabular / figure / algorithm / equation / align 等 | 表格数字被算成"证据"（665 个，7.0/百词）；表格行产生 0 词"句子"，极短句占比虚高到 43% |
| `clean_tex` | 引用、`\ref`、所有层级标题、定理环境可选参数 | `\section{Method: \method{}}` 因嵌套花括号匹配失败，整节从分节统计里消失 |
| `drop_heading_lines` | `#` 开头的行 | 标题行与正文粘成一段，导致**每节首段被整段丢弃** |

因此所有密度指标的口径是**正文散文**：表里的数字不算证据，图注、算法伪码、公式都不计入。

另外三条：

- **碎片句剔除**：剥掉 display math 后残留的 `Then` / `and` / `Define` 不足 4 词，不进句长分布（否则 CV 与极短句比例失真）。它们会作为噪声存在，但不影响阈值判断。
- **`---` 与 `--`**：LaTeX 里 `---` 是 em dash、`--` 多数是数值区间，都计入破折号一次。这是唯一按源码而非清洗后文本判断的指标，只在识别为 LaTeX 时启用。
- **Markdown 结构**：表格分隔线 `|---|` 与列表项开头的 `- ` 用的是同一个字形，统计标点前会先剔掉，否则每一行表格都算三个破折号。同理，`is_tex` 判据要求 `\section` 这类命令出现在行首，避免一篇只在代码块里引用 `\section` 的文档被当成 LaTeX 解析。

改这一层之后必须跑 `tests/run_cases.py`：其中 5 条不变量是 LaTeX 5 个 bug 的护栏，2 条是 Markdown 结构与英文非论文模式。

## 一、通用指标（中英都算）

| 指标 | 定义 | 意义 |
|---|---|---|
| 句长均值 / 标准差 / CV | 中文按字符、英文按词切句；CV = 标准差 ÷ 均值 | 最稳的跨语言判据。人类长短交错，模型向均值收缩 |
| 极短句 / 超长句占比 | 中文 <8 字 />80 字；英文 <5 词 />35 词 | 人类有长尾，模型很少有真正的极短句和长句 |
| 标点类别数与熵 | 11 类标点计数 + 香农熵 | 类别数少 = 单调。**这条路比"数破折号"稳**，见第三节 |
| 破折号 / 分号 / 括号 / 问号密度 | 每千字或每千词 | 破折号高密度是 2022–2026.9 的历史指标；只认 `—` `–` 与前后带空格的 `-` / `--`，不认 `state-of-the-art` 里的连字符 |
| AI 词表命中密度 | 固定词表精确匹配 | 单词命中是噪声，密度是信号 |
| 连接词起句率 | 以连接词开头的句子占比 | 中文靠语义衔接；超过三成说明在硬拼段落 |
| Markdown 脚手架 | 粗体 / 标题 / 列表 / 行内代码计数 | 正文里大量粗体与列表 = 聊天输出直接粘贴 |
| 重复 n-gram 占比 | 中文 5 字 / 英文 4 词滑窗 | 检测"单点稀释" |
| 段落长度 CV | 各段字数的离散度 | 每段体量接近是模板副产品 |
| 语气词 / 人称密度（中） | 啊呢吧吗嘛；我 / 我们 / 你 | 语气词缺失造成冰冷感 |
| hedge 密度（英） | may / might / could / potentially 等 | 情态词堆叠是"欠断言"的量化形式 |
| copula 回避（英） | serves as / represents / boasts 等 | 用复杂结构替换 is / has，跨代际稳定 |

## 二、论文指标（`--paper`）

| 指标 | 定义 | 为什么单列 |
|---|---|---|
| 数字数 / 密度（每百词） | 算作证据的数值，**排除 Table 3、Section 4.2 这类指针，也排除表内数字** | 论文的强弱由数字承载，不由形容词承载 |
| 8–20 词带占比 | 句长落在这个区间的句子比例 | 新模型被压制破折号后挤进这个带；>80% 且样本够长就该查 |
| 评价性形容词计数 | novel / significant / comprehensive / superior 等 27 个 | **论文体第一大痕迹**：用形容词替代数字 |
| 动词阶梯分布 | prove·guarantee / show·demonstrate / improve·observe / suggest·may 四层；`guarantee` 只有作动词（guarantee that / convergence…）才计入，名词用法单列 | 看有没有越界（只有实验却写 prove），也看有没有过度示弱。**有定理环境时 prove 不报高危**，只提示核对编号 |
| 空承诺句式 | `extensive experiments demonstrate the effectiveness` 等 16 个正则；**同段有具体数字则不计** | 命中后先看邻段有没有证据；有数字的"validate the effectiveness"不是空话 |
| 虚指归因 | `recent studies have shown` / `most existing methods` 等 7 个正则 | 判据：能否立刻写出 2–3 篇具体文献+年份 |
| hedge 堆叠 | 同一句内 ≥2 个情态词 | 比总密度更准，堆积通常发生在限定句 |
| significantly 无检验 | 逐句判断，窗口取前后各一句，查 p 值 / ± / std / seeds / CI | 论文里最容易被审稿人抓的一条 |
| 名词化密度 | -tion / -ment / -ance / -ity 等后缀占比 | 动词被抽成名词后，责任主体消失 |
| claim 锚点 | Table / Fig / § / `\ref{}` 计数 | 锚点太少说明 claim 没有证据位置 |
| 分节词数 | 按 `\section{}` / `##` 切分 | 快速看摘要是否超长、Related Work 是否失控 |
| 摘要专项 | 词数、数字数、是否以背景开头 | 三个指标就能判断摘要是不是引言压缩版 |

## 三、阈值纪律

脚本里的告警线**没有实验依据支撑为普适判据**，只用于排序关注：

| 指标 | 通用 | 论文模式 |
|---|---|---|
| 句长 CV | <0.30 高 / <0.40 中 | <0.20 高 / <0.26 中（学术句长本来就集中，放宽） |
| 标点类别数 | <4（中文）/ <3（英文） | 同 |
| 词表密度 | >8/千单位 高 / >4 中 | 同 |
| 评价性形容词 | — | >3/百词 高 / >1.5 中 |
| 数字密度 | — | <1/百词（且 >400 词）中 |
| 锚点 | — | <3（且 >800 词）中 |

四条使用纪律：

1. **不看单项，看三项以上同时偏。**
2. 样本 <300 单位时密度类指标不稳定，只看方向。
3. 学术文本的四字格、名词化、被动本来就多，别把体裁特征当 AI 味。
4. 告警只决定"先看哪里"，不决定"是不是 AI 写的"。

**标点这条特别说明**：不要用"破折号数量"当判据。2026 年 7 月的研究里 ChatGPT 用破折号已经比专业作家少，因为 GPT-5.1 起被硬性压制。所以脚本只报破折号密度，判定改用"标点类别数"——把所有破折号删光、只剩逗号句号，才是现在更常见的形态。

## 四、脚本测不出什么（必须人工）

| 查不出的问题 | 为什么重要 | 怎么查 |
|---|---|---|
| 语义空转 | 语法完整、词表干净，但删掉后信息量不变 | 逐句问：删掉这句，读者会少知道一件事吗 |
| 虚构来源 | 引用不存在的文献、机构、数字 | 逐条核对原始出处 |
| 因果越界 | 相关性写成因果 | 看研究设计 |
| 论证链断裂 | 每句都对，连起来推不出来 | 写出论证骨架再核 |
| claim 与证据错配 | 引用了 Table 3，但 Table 3 不支持这句话 | 逐条对表 |
| 词性比例、成语密度 | 需分词与词性标注 | 需 jieba / LTP，本脚本刻意不引 |
| 语域错配 | 学术混口语，或科普混术语墙 | 人读 |
| 引号内举例被误计 | 脚本分不清"使用"与"引用" | 看命中位置 |

最后一条在实测中出现过：改写稿里为举反例保留了一处 `显著提升`，脚本照样计数。这类误计无解，只能人工核。

脚本的价值是**压缩"看哪里"的范围**，不是替代阅读。把脚本输出当结论，正是本技能要防的那种表面作业。

## 五、扩展

要补词性与四字格密度，需在隔离环境装分词器，不要污染全局：

```bash
python3 -m venv ~/.venvs/prose
~/.venvs/prose/bin/pip install jieba
```

实现后必须重新标定：`tells-zh.md` 第四节的参考值来自特定语料，跨体裁迁移会失效。改完阈值先跑 `tests/run_cases.py`。
